For people who run many Claude Code sessions

The conductor for your Claude sessions.

Thalamus is a small Windows tray app. It sees every Claude Code session you run, keeps your shells alive, tells you when one is waiting for you, and shows how much of your limits is left.

The problem

Five sessions. Five windows. One has been waiting for 40 minutes.

Claude Code works best when you run several sessions side by side: one per project, sometimes more. But the terminals pile up, a session quietly finishes and waits for an answer, and you only notice when you happen to switch to it. Close the wrong window and the session is gone. And somewhere in the background your 5-hour limit is running down.

Without Thalamus
Click through every terminal to see which one needs you. Guess how much of the limit is left. Lose a long-running shell because a window closed.
With Thalamus
One board shows every session by project, amber when it waits for you, with a notification. Shells live in a background process and survive the window. Your limits sit in the top bar.

Everything that runs, on one screen.

Sessions are grouped by Work, Private and General, taken from your project folders. Terminals sit below as windows of their own, each with minimise, maximise and close.

What it does today

Built for a full day of sessions.

Sees every session

Every Claude Code session reports in, whether you start it in Thalamus, Windows Terminal or your editor. Project and category come from the folder.

Knows when one waits

Amber on the board and a Windows notification as soon as a session finished its turn or needs your approval, with Claude's last message.

Shells that survive

Terminals run in a background process. Close the window, restart it, update the app: your shells and Claude sessions keep running.

A window per terminal

Tile them, minimise them, maximise one. The keys you know from Windows Terminal: selection, copy and paste, find, zoom.

Limits at a glance

What is left of your 5-hour and weekly limits, with reset times, right in the top bar. Amber when it gets tight, red when it is nearly gone.

Usage history

Tokens per day, week or month, by project and by model, from Claude Code's own transcripts. Kept as daily totals, so the history stays.

How it works

Small pieces, all on your laptop.

Thalamus uses what Claude Code already offers: hooks and the status line. No extension, no proxy in front of the API, no account.

Claude Code sessions

In any terminal. Hooks report start, prompts, tool use, waiting and end. The status line reports limits and model.

→ 127.0.0.1 →

Thalamus

Tray app with the board, notifications, usage and the terminal windows. Updates itself from GitHub releases.

⇄ pipe ⇄

Shell host

A background process that owns your terminals, so they outlive the window and every update.

Private by design

Nothing leaves your laptop.

Thalamus has no server and no telemetry. It only listens on your own machine, and it only reads what Claude Code writes on it.

  • Local only. The server listens on 127.0.0.1, needs a per-install token and refuses anything a web page could send.
  • Report-only hooks. The token Claude's hooks use can report events, nothing else. It cannot start, read or control a shell.
  • Read-only transcripts. Usage comes from Claude Code's own session files, read and never changed. Your login is never touched.
  • Your settings, your call. Hooks are added to your Claude settings only after you see the exact change and confirm it. A backup is made first.

Works well with Engram

Thalamus runs your sessions. Engram remembers them.

Engram is the memory your AI keeps: every session writes what it did and decided into a local memory, and the next session starts from there instead of from zero. Thalamus and Engram sit side by side in the tray: one shows what is running right now, the other what was learned along the way.

Both organise work by project and keep everything on your laptop. Filing captured ideas straight into Engram is on the Thalamus roadmap.

A good pair
Start a session from the Thalamus cockpit, and it picks up its project's memory through Engram. When it finishes, Thalamus tells you; Engram has already written down what happened.

Install

Up and running in two minutes.

  1. Download the installer

    Get Thalamus-Setup.exe from the latest release.

  2. Trust the signing certificate (once)

    Thalamus is signed with its own certificate, not one bought from a certificate authority. Windows has to be told to trust it once, otherwise the installer shows "Unknown publisher" and automatic updates are refused. Run this in PowerShell; it downloads the public certificate, checks its fingerprint and adds it for your user only (Windows asks you to confirm):

    $c = "$env:TEMP\thalamus-code-signing.cer"
Invoke-WebRequest https://martindroneharmony.github.io/thalamus-releases/thalamus-code-signing.cer -OutFile $c
if ((Get-PfxCertificate $c).Thumbprint -ne '3FD6F579455657834DBD444A55B9FC38F8CD8C49') { throw 'Fingerprint does not match, do not install.' }
Import-Certificate $c -CertStoreLocation Cert:\CurrentUser\Root | Out-Null
Import-Certificate $c -CertStoreLocation Cert:\CurrentUser\TrustedPublisher | Out-Null

    The certificate can only sign programs (nothing else, such as websites) and expires in October 2031. To remove it later, delete Thalamus Code Signing from both stores in certmgr.msc.

  3. Run it

    It installs for your user only, no admin rights needed. The publisher shows as Thalamus Code Signing. As a new program it may still meet "Windows protected your PC": choose More info, then Run anyway.

  4. Find it in the tray

    Thalamus starts with Windows and lives in the tray. Click the icon to open the cockpit.

  5. Let your sessions report

    Click Set up the hooks…. Thalamus shows exactly what it adds to your Claude settings and makes a backup first.

  6. Start Claude anywhere

    Run claude in any terminal, or use New Claude session… in Thalamus. The session appears on the board.

  7. Optional: limits in the top bar

    If you use a Claude status line script in PowerShell, add this so it also passes the limits to Thalamus ($raw is the JSON your script read from standard input):

    try { $t = Get-Content "$env:LOCALAPPDATA\Thalamus\report.json" -Raw -ErrorAction Stop | ConvertFrom-Json
      Invoke-RestMethod -Uri $t.url -Method Post -Headers @{ Authorization = "Bearer $($t.token)" } `
        -ContentType 'application/json' -Body $raw -TimeoutSec 1 | Out-Null } catch {}
